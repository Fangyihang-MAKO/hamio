# Ha!mio 角色创作间

这是可操作的四步网页界面。图片生成和人设润色接口尚未连接，没有真正绘图或 AI 聊天，也不会调用模型或收取生成费用。
示例图复用网站已有流萤素材，也可以手动导入自己的图片；付费、用户账号和桌宠安装包制作均不在本次范围内。现有 Android、Windows 安装包保持不变。

## 当前流程

1. 添加角色参考图片，设置描述、风格和候选数量；使用明确标注的流萤示例体验候选选择。
2. 确认一张角色图，选择一个或多个姿态；添加姿势参考图和修改备注，手动导入姿态成品图片，比较或恢复最近的旧版本。可针对不满意的姿态准备单独的重做请求，保留其他卡片。
3. 输入角色提示词，补充身份、性格、关系、说话习惯、经历、互动边界、开场白和台词示例。页面在本地按这些字段整理提示词，不推断用户未填写的信息。
4. 在模拟桌面中拖动、点击角色，指定点击、拖动、工作、休息各自使用的图片，模拟靠左或靠右工作与休息。可调整大小、不透明度和晃动幅度，查看自己写的开场白。编辑进度自动保存在此浏览器，也可导出设计文件备份后重新导入。

## 姿态编辑与版本

- 每个姿态可单独添加一张姿势参考图，并填写最多 600 个字符的修改备注。参考图只用于描述姿势，不会直接替换角色或成为姿态结果。
- 「导入姿态图片」可把自己准备好的 PNG、JPEG、WebP 成品放到对应姿态卡片上；这是手动导入素材，没有执行 AI 生成，图片来源记为 `reference`。
- 每个姿态保留当前图片和最近 4 个旧版本。旧版本按图片 ID 去重，不包含当前版本；可并排比较，并用「用回这一版」恢复。恢复时，被替换的当前版本也进入历史，超过 4 个的最旧版本不再保留。
- 「只重做这张」只提交该姿态及其修改要求；服务未接入时会提示不可用并保留已有图片，不会把示例冒充新生成结果。

## 人设与提示词

- 不需要生成好姿态即可进入第三步；在角色已确认的前提下，可以先写人设。
- `persona.js` 的 `compilePersonaPrompt(draft)` 只是本地文本编排，不是 AI 推理。台词预览只展示填写的文字，不会自动回复。
- 流萤示例为预先编写的角色扮演设定，只有选中流萤示例图片时显示入口；不会自动套到其他角色上。
- 输入会随本地草稿自动保存。切换步骤、重新确认同一角色会保留人设；更换角色或重新开始会清空人设。
- `保存完整设计 JSON` 使用 `schemaVersion: 4`，包含 `persona: {brief, fields, source, systemPrompt}`。`source` 为 `manual`、`demo` 或 `generated`，记录这版人设的来源。人设 TXT 可单独下载或复制。

## 试养与项目保存

- `preview.js` 只使用当前已确认的角色和实际已有的姿态图片。没有其他姿态时仍可拖动基础形象，不会套用其他角色的动作。
- 点击角色会触发点击映射，拖动会触发拖动映射并在松手后回到基础形象；拖动不会额外触发点击互动。姿态按钮可直接选择图片，解码完成后淡入淡出。方向键可移动角色，Shift + 方向键加快移动，回车触发点击互动。
- 点击、拖动、工作、休息四种互动都可选择自动匹配、基础形象或已有姿态。自动匹配时，点击优先用害羞、其次开心，拖动用拖拽，工作用探头，休息优先用困倦、其次睡觉；缺图时明确提示，拖动保留当前图片，其余互动回到基础形象。工作按钮可模拟靠左、靠右，休息按钮可模拟休息，「恢复日常」回到基础形象。这些是静态图片与轻晃的网页模拟，不会检测真实工作或休息状态。
- 气泡展示手写开场白，不会调用聊天 AI。预览限于网页内，不会在操作系统桌面或其他应用上悬浮。
- 离开第四步、隐藏标签页或系统开启减少动态效果时暂停晃动。设置为 0% 时关闭晃动。
- 导出文件内嵌角色参考图、全部候选图、姿态参考图、当前姿态图和最近 4 个旧版本，保留自定义姿态、修改备注、人设、互动映射、大小、不透明度、晃动幅度与相对位置。导出完整设计仍需确认基础形象；保存的是设计项目，不是安装包。
- `project.js` 导出版本 4，并接受版本 1、2、3、4 的项目。旧文件会补上空姿态参考、修改备注和历史，以及默认互动映射；导入时重新整理提示词，不执行导入文件中的脚本或外部链接。
- 版本 4 的 `poseDefinitions[]` 增加 `referenceImage` 和 `editNote`，`poses[]` 增加最多 4 张图片的 `history`；`previewSettings.bindings` 包含 `click`、`drag`、`work`、`rest`，每项为 `null`（自动匹配）、`base` 或 `pose:<已定义姿态 ID>`。已绑定的姿态暂时没有图片时也可保留设置。
- 文件上限 100 MiB，每张图片上限 10 MiB；仅支持内嵌 PNG、JPEG、WebP。图片验证和解码通过后才询问是否替换当前设计，文件损坏或取消导入会保留当前设计。

## 本地自动保存与备份

- `drafts.js` 使用 IndexedDB 保存一份本地草稿，图片不放入 `localStorage`，不会自动上传、保存到账号或跨设备同步。同一浏览器、同一网站来源（协议、域名和端口）共用一份草稿；不同路径不单独隔离。
- 尚未确认形象、没有选中候选、只写了文字或尚未提交自定义姿态时，也会保存进度。刷新后读取草稿，恢复已保存的图片、人设、步骤和试养设置；恢复时重新编排提示词。
- 修改后稍等页顶显示「已自动保存」，或点击「立即保存」并等到保存成功，再关闭或刷新。页面离开时的最后一次异步写入无法保证完成；出现「草稿未保存」时，请保留页面并处理错误，已有完整设计可先导出备份。
- 草稿上限 100 MiB。浏览器禁用存储、空间不足或读取失败时会明确报错；不会静默使用旧缓存。清理浏览器数据会丢失草稿，更换浏览器、设备或网站来源也不会自动带过去。请定期导出设计 JSON，需要时从页顶「导入设计」继续。
- 「重新开始」会清除当前设计和这份本地草稿。每次导出得到独立备份文件，不受之后草稿修改或浏览器数据清理影响。

## 留给后续人设服务的接口

```js
setPersonaAdapter({ refinePersona });
getPersonaStatus();
refinePersona({ draft: { brief, fields }, characterId }, { signal });
// 返回 { draft: { brief, fields }, source: 'generated' }
```

默认没有 adapter，`refinePersona` 拒绝并返回错误码 `PERSONA_NOT_CONFIGURED`，不会发送网络请求。后续适配器只接收人设文字和角色 ID，不发送参考图片。返回的建议先展示，用户点击采纳后才替换表单。请求期间修改文字、换角色或重置会取消请求并忽略过期结果。服务商配置与密钥不放入公开网站或导出文件。

上传图在此浏览器中处理，并随本地草稿保存到 IndexedDB。没有自动上传、账号保存或跨设备同步。
未接入服务时点击生成会说明服务未接入，不会将旧素材冒充生成结果。

## 留给后续图片服务的接口

`api.js` 暴露：

```js
getGenerationStatus(); // { configured: false, label: '图片生成接口待接入' }
generateChibi(request, { signal });
generatePoses(request, { signal });
setGenerationAdapter({ generateChibi, generatePoses });
```

默认不安装 adapter，两种生成方法都抛出 `GenerationUnavailableError`，错误码为 `GENERATION_NOT_CONFIGURED`。
后续在可信应用代码中安装 adapter，由它完成上传、提交任务、轮询进度并返回最终图片。UI 无需知道模型提供方。

Q 版请求的建议结构：

```json
{
  "references": [{ "id": "ref-1", "name": "character.png", "dataUrl": "data:image/png;base64,..." }],
  "description": "角色特征及希望保留的细节",
  "style": "soft",
  "count": 4
}
```

姿态请求的建议结构：

```json
{
  "baseImage": { "id": "chosen-chibi", "dataUrl": "data:image/png;base64,...", "source": "reference" },
  "poses": [{
    "id": "happy",
    "name": "开心",
    "description": "双手靠近脸颊，保持服装和画风",
    "editNote": "保留头部倾斜，只调整双手位置",
    "referenceImage": { "id": "pose-ref-1", "name": "姿势参考.png", "dataUrl": "data:image/png;base64,...", "source": "reference" },
    "currentImage": { "id": "happy-v1", "dataUrl": "data:image/png;base64,...", "poseId": "happy", "source": "reference" }
  }],
  "revision": 1
}
```

`editNote` 没有内容时为 `""`；`referenceImage` 和 `currentImage` 没有图片时为 `null`。`referenceImage` 提供姿势参考，`currentImage` 提供当前版本以便定向修改；它们与基础形象、姿态描述一起提交。当前没有 adapter，准备这些内容不会发送到外部服务。

两种方法返回：

```json
{
  "images": [
    { "id": "unique-result-id", "dataUrl": "data:image/png;base64,...", "poseId": "happy", "source": "generated" }
  ]
}
```

`dataUrl` 必须为 PNG/JPEG/WebP 的 base64 data URL，方便下载与保存完整设计记录。若服务商返回图片 URL，由后端适配器获取并转换，不把临时链接或服务商密钥交给前端。`source` 必填，取 `generated` 或 `demo`。
`poseId` 用于把返回图片匹配到对应姿态，服务必须只返回请求指定的姿态。示例不可标为 `generated`。
重新绘制时保持同一个姿态 ID、使用新的结果 ID；保留未重做的姿态。
切换角色时增加 revision 并取消旧请求，忽略过期响应。adapter 应响应传入的 `AbortSignal`。

后续 HTTP 服务可采用：

- `POST /api/studio/assets`：上传图片并获得素材 ID。
- `POST /api/studio/jobs`：提交 Q 版或姿态任务。
- `GET /api/studio/jobs/:jobId`：逐张查询状态和结果。

这些是接入约定，不是当前已经部署的服务器。生成服务的 API 密钥只能放在后端，不能写进静态网站、GitHub 或导出的设计记录。
开放真实生成前需增加身份校验、调用限额和服务端输入校验，并明确图片发送到哪家服务。

## 创作概览与素材包

页面会按当前设计提示四项准备情况：已确认的形象、所选姿态、基本人设、说话方式与开场白。点击提示可回到对应输入位置。缺项只作建议，不阻止保存；沿用上一版的待重做姿态不会标成已完成。

第四步的「导出创作包 ZIP」在浏览器本地整理以下文件，不调用模型：

- `project.json`：schema 4 的完整设计，包括参考图、候选、修改备注、历史版本与预览设置，可重新导入
- `images/`：基础形象和所有当前姿态图片，保留原始图片字节；未选中的已有姿态也保留
- `persona.txt`：按填写内容编译的人设提示词
- `manifest.json`：图片来源、姿态对应关系和未准备的素材清单
- `README.txt`：面向用户的恢复与使用说明

创作包不是 APK / EXE。无图姿态不会用参考或历史图片补位；这些材料只保存在完整设计 JSON 中。自动草稿、JSON 单独导出和旧版项目导入继续可用。ZIP 使用 UTF-8 文件名、标准 store 格式及 CRC32；项目限制 100 MiB，创作包上限 180 MiB。

## 本地预览

在 `github-pages/` 目录启动静态 HTTP 服务，打开 `/studio/`。需要通过 HTTP 访问 ES modules，不能双击 `index.html` 以 file URL 打开。
此页无需 npm 安装或构建，可随现有 GitHub Pages 网站发布。
